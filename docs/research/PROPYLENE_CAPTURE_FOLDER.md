# Four-case capture-folder plan

Planned 15 November 2026 before implementation. This prepares the supervised capture step of [propylene qualification](FIRST_PHYSICS_QUALIFICATION.md) using the existing [frozen cases](PROPYLENE_PREPARATION.md), output-semantics contract and unit-transcription templates. It reduces manual template assembly; it does not run ALOHA or resolve source applicability.

## Scope and acceptance

1. Add one standard-library CLI under research/dispersion that creates a fresh local capture folder for baseline, rate-half, rate-double and wind-higher.
2. Generate `NAME-capture.json` from the existing observation template with unconfirmed output-semantics and raw-unit transcription supplements attached. Observed inputs, run time, engine hash, method, values, warnings/reviews and evidence remain unset/empty. Preserve run_completed=false and all qualification flags=false.
3. Keep frozen case snapshots under a separate inputs directory; never copy intended inputs or expected reference answers into observed fields. Add separate empty evidence directories, a local workflow guide and a setup manifest linking cases and generated file hashes.
4. Validate and serialize the whole package before creating the destination. Refuse any existing destination. Write the manifest last as a completion marker; on a failed write, retain partial files without a valid completion manifest and require a fresh destination. Do not delete/overwrite user material.
5. Test four-case contents and supplements, blank observations, rejection by existing inspectors/normalization, matching case/file hashes, source preservation, existing paths, validation failure, interrupted writes and CLI behaviour. Run full tests and Windows/Linux CI before PR merge.

## Delivery and limits

Plan commit first on codex/propylene-capture-folder, then implementation, tests, PR, diff/CI review and merge. Work is CLI-only. Only disposable test folders will be generated in this task. Actual physics results, model applicability, human evidence review and dashboard physics remain pending. A setup manifest attests initial generated bytes only; manually completed records must pass the existing run/evidence checks separately.

## Future preparation command

From the repository root, use a new local folder under ignored outputs:

```powershell
python research/dispersion/prepare_capture.py --output outputs/propylene/session-01
```

The folder contains:

- Four `NAME-capture.json` records, each with `run_completed=false`, null observed inputs/results/run time/method/engine hash, empty evidence and unconfirmed output-semantics/transcription supplements.
- `inputs/NAME.json`, separate copies of the registered assumed cases. They are intended inputs, not observed model-entry evidence.
- Empty `evidence/NAME/` directories and a plain-text guide for future manual capture, normalization, inspection, comparison and local review export.
- `capture-manifest.json`, written last, with case identities and initial generated-file SHA-256/byte counts. All physical-qualification and dashboard flags remain false.

The manifest describes the initial blank setup. After genuine observations are transcribed, capture-file hashes will differ by design; it must never substitute for existing record/evidence inspection. Both supplements stay unconfirmed until an operator records actual evidence. Do not copy expected values or case snapshots into observed fields merely to pass checks.

All inputs are validated and payloads serialized before destination creation. Existing directories (including empty ones), files and linked destinations are refused. Writes use exclusive file creation. Failure can leave partial files, including a malformed final manifest; these are not a successful setup. Preserve partial material and retry with a fresh directory. A valid complete manifest and its listed initial files/hashes describe a completed initial setup; existence of the manifest filename alone is insufficient. This is not a transactional or power-loss-proof storage system.

Source-state applicability must still be resolved before the supervised model run. No model is launched by this tool, no evidence is collected automatically, no case values are silently revised, and no dashboard adapter is enabled.
